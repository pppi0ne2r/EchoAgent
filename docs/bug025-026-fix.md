# BUG-025 / BUG-026 修复记录

日期：2026-10-23（Asia/Shanghai）  
范围：密码分支的候选契约与 RSA 独立验证输入格式。  
背景：项目 #45（HAVE_FUN）实测中，模型 3 步内给出正确候选，但首个候选因 `observation_kind` 字段被拒，最终因验证器不支持题目输入形态而无法完成。用户已提交平台确认候选正确。

## 1. 问题

- **BUG-025**：候选提示词只要求 `crypto.fact.claim_status=candidate`，未约束 `crypto.fact.observation_kind`；模型写 `candidate`，`fact_crypto()` 拒绝，候选保存失败、intent 记 error。
- **BUG-026**：`extract_rsa()` 只接受 `n/e/c` 顶层字面量，题目文件采用 `e:…`、`p:…`、`q:…`、`c = pow(flag,e,p*q)` 加 `#<c>` 注释，验证始终 `inconclusive`。

## 2. 改动

### 2.1 候选契约（BUG-025）

- `echo_agent/dispatcher/prompts.py`：`_crypto_contract_rules()` 增加 `observation_kind` 枚举约束；first_run/explore 的候选说明同步。
- `echo_agent/dispatcher/core.py`：`_save_crypto_candidate()` 保存前强制 `metadata["observation_kind"] = "evidence"`；候选身份仍由 `claim_status` 与 `FactKind.CANDIDATE` 表达。契约本身保持严格。
- `container/AGENTS.md`：同步约束（需重建 worker 镜像才进入容器；提示词不依赖镜像）。

### 2.2 输入解析（BUG-026）

`echo_agent/crypto_inputs.py`：

- 参数扩展为 `n/e/c/p/q`。
- 顶层允许：`name = <int>`、`name: <int>`（AnnAssign 注解为 int 且无 value）、唯一一条 `c = pow(<未知明文名>, <指数>, <模数>)`。
- `p,q` 成对出现时推导 `n=p*q`；与显式 `n` 必须一致。
- 符号密文取同一输入中唯一一条「仅含十进制整数」的注释行。
- 受限求值器只支持 int 常量、已解析参数名、`+ - * // %`、一元 `+/-`；节点预算 64、结果位长 4096；禁止调用、属性、下标、`**`、导入、控制流；从不执行上传代码。

### 2.3 验证与答案表示（BUG-026）

`echo_agent/crypto_verify.py`（`VERSION = crypto-verify-v4`）：

- `_rsa_input()` 接受并校验 `p=`、`q=`（成对、`p*q==n`）。
- `_verify_rsa()` 候选未给因子时使用输入侧 `p,q` 计算 `lam` 与 `unique_root`，记录 `checks.factors_source`。
- 核心检查仍是 `pow(m,e,n)==c`。
- 明文候选需能取得十进制 `m`；answer 可为 decimal、hex、完整 UTF-8 明文或明文中一段非空连续子串；记录 `answer_relation`、`answer_offset`、`plaintext_sha256`、`plaintext_length`。
- 格式由内层模型按题面判断；多根题在 `solution_policy=any` 下放行，`unique` 仍如实 `inconclusive`。

### 2.4 提示词 / 容器指引

- RSA 明文候选必须给出十进制 `m`，answer 按题面填写（完整明文、`flag{}`/`CTF{}` 内层或裸串均可），不假定固定 wrapper。
- 支持范围补充 `p/q`、`n=p*q`、`c = pow(...)` 与整数注释密文。
- 多根说明与 `solution_policy=any` 的建项要求。

## 3. 测试

新增 `tests/test_bug025_026.py` 11 项：

- 候选 `observation_kind=candidate` 归一化保存且 answer 不丢；三个提示词与 AGENTS.md 约束。
- 本题格式解析（`e:…`、`p:…`、`q:…`、`pow`、注释密文）；`n=p*q` 推导。
- 注释密文 0/2 条拒绝；`pow` 的调用/属性/下标/`**` 拒绝；`n=5*11` 与 `globals()['c']` 仍拒绝。
- 输入因子唯一性、完整明文/内层子串通过、错误子串与缺 `m` 不通过、多根 `any` 通过、dispatcher 端到端 completed。

结果：

- 定向相关 159 项通过，1 项宿主机可选 AES 检查跳过。
- 全套 308 项：302 通过、1 跳过、5 项为已知 Windows 环境失败（4 项商店桩 `python3` + 1 项 NTFS `chmod`）。
- **真实数据离线重放**：用项目 #45 的原始附件与 fact 9 的候选（`m` 十进制、answer 为 `flag{}` 内层串）构造 `solution_policy=any` 的临时项目，`verify_candidate()` 返回 `pass`：`factors_source=input`、`unique_root=false`、`answer_relation=substring`（offset 5）、`ciphertext_matches=true`、`goal_satisfied=true`。这不是模型复跑，但证明修复对本题真实输入有效。
- 未重建镜像、未重启服务、未重跑真实模型。
