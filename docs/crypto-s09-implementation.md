## 已交付实现及适用条件

以下描述以按契约填写的候选、已有 HTTP 验证接口及支持的输入格式为前提。它不是对所有客户端、缺字段输出和状态修改入口的完成保证；缺口见下文。

- 密码 worker 的 `crypto.fact.claim_status=candidate` 配合 `crypto.candidate` 保存为单独的 `candidate` fact，保留候选来源、输入 ID、生产 intent、可选脚本/产物引用。它不会进入 evidence 或作为可规划的已证明事实。reason 只有一个字符串答案时也可生成候选 fact；不能由此直接完成。
- `verify.candidate` intent 由调度器直接调用服务端校验接口，不通过同一个求解 worker 自报 `verified`。服务端重新读取原始输入并核对字节大小和 SHA-256；若候选引用产物，也重新核对每个产物。记录保存候选 fact 摘要、原始输入和产物引用、方法版本、实际检查项及 `pass/fail/inconclusive`。重复调用可重算；完成前再次重算并逐项比对记录。输入、候选或产物修改后不能凭旧记录放行。
- RSA 输入当前支持单个 ASCII 文件中的唯一 `n=...`、`e=...`、`c=...` 行。明文验证检查范围和 `m^e mod n=c`；提供 `p,q` 时检查乘积和素性，提供 `d` 时检查模最小公倍数的逆元及解密回代。因子和私钥也可作为独立答案类型。小于等于 10000 的模数枚举并记录所有根；较大模数没有可判定唯一性依据时返回 `inconclusive`，不以可打印文本或 flag 格式放行。
- AES 输入当前支持 JSON 清单的 GCM/CBC。校验会检查模式、nonce/IV、GCM tag、CBC 填充及原始输入给出的 `known_plaintext_sha256`；GCM 必须认证通过，且解出内容与已知哈希和候选答案都匹配。缺少已知哈希或必要参数时返回 `inconclusive`。服务端优先使用本机 AES 库；本机未安装时，通过只读源码挂载、禁网、256 MiB 内存与 30 秒超时的临时 Docker 容器，复用 S03 镜像已有的 PyCryptodome。容器不可用也返回 `inconclusive`。可选安装项 `pip install -e '.[crypto-verify]'` 可免去该回退；核心 Web/RSA 路径不增加强制依赖。
- 原 Web 项目的答案来源判断保持原逻辑。密码完成只读取当前仍可重验的 `pass` 记录，连到 goal；模型单独声称完成、验证失败或无法判定都不放行。项目设置 `require_platform_acceptance=true` 时不会仅凭本地校验完成；系统目前没有受信的平台回执通道，因此此类任务保持待验。没有真实平台回执时只表示本地独立验证通过。

## 最新复审发现（2026-10-22）

- **入口未贯通：** `StoreDispatcherClient` 没有 `verify_crypto_candidate`，网页后台无法按 HTTP 路径完成相同验证；现有调度测试替身自行实现了该方法。
- **完成语义不足：** 因子、私钥和明文由候选选择，未与项目目标绑定。`unique_root=False` 仍可返回 `pass`，完成门槛未区分任一解和唯一解要求。多根测试记录集合并期待 `pass`，不等于已验证唯一答案策略。
- **候选隔离非强制：** 省略 `crypto` 或候选标记会进入其他结果处理路径；候选保存失败可能静默返回。前文隔离效果仅在合规输出路径成立。
- **支持范围窄：** 验证要求单输入和特定 RSA/AES 格式，没有贯通多输入、源码提取、RSA 字节答案以及首版计划中的其他题型。AES 强制要求原题明文哈希并不适用于全部正常题目。
- **运行与状态边界：** HTTP 请求 10 秒超时与 Docker 验证 30 秒不一致；验证进程未接入 worker 停止管理；状态更新接口没有统一完成验证。平台回执只有保守阻断，没有受信接收流程。

上述是待修复或待明确的边界，不是本轮已实现功能。具体代码位置、影响、整改顺序和未来验收条件见复审报告 R01–R10。

## 范围与待核实

- 本机单进程 AES 单测因未安装可选库而跳过；真实 Docker 服务端回退正反例历史检查已通过。部署时须让服务进程能调用 `docker` 且本地有 S03 镜像，或安装可选宿主机依赖；两者皆不可用时保守返回 `inconclusive`。Docker 回退每次启动临时容器，具体延迟仍需按环境核实；超时或异常会尝试强制移除该容器，不能据此保证所有取消情形都已覆盖。
- 验证器设有 1 MiB 单输入和 4096 bit RSA 模数限制，但这些不等同于完整的 S08 硬预算：输入哈希先于 1 MiB 检查，产物会全量哈希，宿主机验算没有统一硬超时与总并发限制。复杂文件格式、多输入、一般多解集合枚举和大模数的素性严格证明尚不支持；应明确返回范围不足或无法判定，后续增加受控验证方法。
- 这不是 CTF 平台提交回执。若题目要求平台确认，仍需实际获得并另行记录接受回执，不能把本地 `pass` 写成“平台接受”。
