## 1. 目标与边界

在现有 EchoAgent 中接入密码题能力，保留 `first_run → explore → reason`、fact/intent 图、每项目一个 worker 容器的主体架构。优先实现低配置、可复现、有计算预算、有证据和验证记录的离线解题流程。

第一版覆盖：

- 编码与字节处理、异或、常见 RSA 弱点。
- 对称密码参数与实现问题的分析、已知条件下的解密与验证。
- 简单数论、随机数分析、位运算和约束求解。
- 文件输入、可复用计算产物、候选结果与独立验证。

暂不纳入：

- IDA、逆向、Pwn、移动端、取证等其他方向的工具扩展。
- GPU 破解、分布式搜索、通用远程数学服务、MCP 接入。
- 首版强制安装 SageMath；复杂格、有限域和椭圆曲线等能力后续按需扩展。
- 承诺破解参数和实现均正确的现代密码。信息不足、预算耗尽也必须有准确的结果描述。

配置目标：继续使用现有模型配置；密码环境在镜像内预装，数据位置与计算限额有默认值，日常运行不要求宿主机配置数学库。

## 3. 实施原则

1. **fact 是已确认的观察或结论。** 猜想写在 intent 中；可打印字符串不自动成为正确答案。
2. **intent 是有边界的验证动作。** 明确输入、前提、方法、关键参数、范围、预算和期望产物。
3. **否定观察也可作为 evidence。** `gcd(n1,n2)=1` 是可复用的事实；被关闭的是当前条件下的共享因子假设。
4. **超时不等于无解。** 求解器 unknown、执行报错、预算耗尽、范围穷尽必须区分。
5. **执行成功不等于解题成功。** 候选、验证通过、题目接受分别记录；没有平台回执时不声称平台已接受。
6. **先最小扩展，不重写图引擎。** 保留主要 from/to；必要时补多事实依赖和产物元数据。
7. **证据可重放。** 保存原始输入、哈希、脚本、参数、工具版本、输出和验证记录。
8. **兼容现有项目。** 新字段有默认值，旧数据库、API 与原有任务行为必须回归核实。

### S02：确定最小数据约定

交付：确定任务如何标记为 crypto；离线输入、fact、intent、计算结果和验证记录如何表达。先写清字段与样例，再实施数据库/API 改动。

建议的最小内容（字段名待实施时确定）：

- 项目：任务类型、输入清单、计算限额；旧项目默认行为保持兼容。
- fact：原有描述与 kind；产物引用、输入哈希、来源 intent、多事实依赖、验证信息。
- intent：原有 from/to；方法标识、关键参数、输入版本、已覆盖范围；需要继续计算时引用检查点。
- 计算结果：正常结束、超时、工具错误、求解器 unknown、穷尽指定范围等原因。
- 验证记录：验证对象哈希、验证规则、执行输出、通过/失败/无法判定。

验收：

- [x] 用同一份 RSA 输入展示“假设 → 计算 → 因子事实 → 候选 → 校验”的数据样例。
- [x] 明确多输入、多产出如何关联，避免只靠自然语言隐含引用。
- [x] 明确大整数以有基数说明的字符串保存，字节保留编码、长度和前导零；不经浮点数传递。
- [x] 明确哪些是结构化数据，哪些只是文件引用，不把矩阵和整份源码塞入 prompt。
- [x] 明确旧记录缺少新字段时的读写行为和迁移方案。

通过条件：有可实施的数据约定；不要求这一阶段已经修改全部模型。

- [x] 在实际 worker 用户下验证导入、模幂、整数开根、对称密码测试向量和简单约束求解。
- [x] 依赖冲突和系统数学库依赖在镜像构建时解决，运行任务不临时安装包。

### S06：适配密码规划与事实语义

交付：密码任务按需加载指引；first_run 整理输入与低成本检查；explore 验证有边界的假设；reason 根据证据规划。

验收：

- [x] 密码任务不再套用上传漏洞、目录扫描等默认示例来规划。
- [x] 显式标记的“可能有弱点”留在假设中，未经检查不写为已验证结论。
- [x] `gcd(n1,n2)=1` 作为可复用 evidence；关闭的是特定共享因子假设。
- [x] 记录“在哪些输入、参数和范围内失败”，不泛化成整类方法无效。
- [x] 超时、unknown、错误不被当成无解；保留现有部分事实保存能力。
- [x] 老 evidence 截断后仍能通过稳定引用找到完整参数与产物。
- [x] 使用固定 worker/reasoner 输出测试数据流；真实模型试跑另行记录，不将提示词文本检查当成行为已验证。

通过条件：固定样例能产生合理、可执行的下一步；错误分类不会锁死合法分支。

### S07：参数化去重和继续计算

交付：去重结合方法、有效输入版本、关键参数和范围；文本相似度仅作辅助；记录继续计算依据。

验收：

- [x] 相同输入/方法/参数/范围的重复计算被识别，即使换了 fact 起点或改写描述。
- [x] 同一方法更换实质参数或输入约束时，不被粗略相似度误拦截。
- [x] 搜索相邻且不重叠的区间可分别执行；扩大范围时能识别已覆盖部分。
- [x] 超时后有检查点或明确的新预算时，可以继续；不能靠换名无限重启相同任务。
- [x] 新增事实确实改变前提时可重新评估旧假设，旧排除结论仍保留适用范围。
- [x] 原有 Web 去重行为按任务类型保留或经过回归确认。

通过条件：同时验证“阻止无效重复”和“允许有依据的重试”，不能只验证其中一个。

### S08：计算预算、超时与清理

交付：为密码计算设置明确的墙钟时间、内存、并发和输出限制；记录计算标识及退出原因；长任务按可实现的方式分块或保存检查点。

验收：

- [x] 初始建议重计算并发为 1，并与模型调用槽位区分。
- [x] 合法无输出计算不会只因模型输出空闲被误分类；同时仍有硬截止时间，不能无限等待。
- [x] 超时保存已确认事实和可用产物，intent 保持未完成/错误语义，不自动证伪。
- [x] 用户停止、进程异常和预算耗尽后，容器内计算子进程确实退出；仅宿主机 `docker exec` 退出不算通过。
- [x] 使用可控测试任务验证时间和资源限制，不通过实际运行不可控的大数分解来验收。
- [x] 有预期的无进展停止行为；不会长期反复规划相同重计算。

通过条件：明确区分计算完成、预算耗尽、求解器 unknown 和基础设施错误，且资源能够回收。

最少测试场景：

| 场景 | 预期 |
| --- | --- |
| 小规模共享素因子 RSA | 参数 → gcd → 因子 → 候选 → 校验 → 完成，证据可重放 |
| 不共享素因子的模数 | 得到 gcd=1 的 evidence，关闭当前假设，允许合理新方向 |
| 对称密码正确样例与篡改样例 | 正确条件通过；错误 tag/参数或不满足约束时不误报成功 |
| 约束问题存在多个模型 | 不将任意一个可行模型当唯一答案 |
| 错误候选已经出现在日志中 | 没有有效数学校验仍不能完成 |
| 十六进制、前导零、大小端输入 | 解释明确且字节不丢失；歧义被报告 |
| 可控超时与停止 | 部分证据保留、退出原因准确、计算进程清理 |
| 参数变化、继续区间、相同计算改名 | 合法继续可执行，无效重复被阻止 |
| 重启或完成后移除容器 | 已保存输入、脚本和验证结果仍可读取 |
| 原有 Web 任务与旧数据库 | 原有入口和核心流程无新增回归 |

验收层次：单元/集成测试、真实镜像计算、完整 dispatcher 试跑分别记录。完整试跑若使用真实模型，记录模型与配置，但不要求模型每次采用相同解题步骤；最终结论与证据必须一致。

通过条件：全部必做步骤通过；与基线相比没有未解释的新失败；真实容器链路已验证。若模型或 Docker 条件缺失，只能标记相应场景待核实。
